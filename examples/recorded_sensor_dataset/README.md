# Recorded timestamped sensor dataset format

This directory documents format version 1. A collected dataset contains:

```text
run-name/
├── manifest.json       # immutable collection metadata and units
├── raw.csv             # immutable asynchronous sensor events
└── processed.csv       # generated by preprocessing; never hand-edited
```

Every CSV row has `timestamp_s` and `clock_id`. Empty fields mean no sample on
that row. Present encoder, IMU, heading, and external-pose samples require their
corresponding explicit validity flag. Counts use `tick`, angles use radians,
angular rates use `rad/s`, distances use metres, and voltage uses volts.

The manifest records clock identity, wheel geometry, ticks/revolution, counter
modulus, direction signs, frames, calibration version, surface, payload, run
type, and independently measured distance or angle where appropriate. Copy the
generated fixture manifest as a schema example:

```bash
PYTHONPATH=src .venv/bin/python scripts/sensor_log_tool.py \
  generate-fixture outputs/recorded_example --run-type straight
```

Generated fixtures are only parser/replay tests. They are not camera, encoder,
IMU, vehicle-dynamics, or estimator validation data.

Collection runs should be separate and named clearly: stationary, straight,
in-place rotation, constant-radius turn, acceleration/braking, and a held-out
general evaluation route. Preserve the original raw log and manifest after
collection; write all derived data to new files or directories.
